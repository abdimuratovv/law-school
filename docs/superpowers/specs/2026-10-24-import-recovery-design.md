# Recover interrupted question imports

User report: the 45-question CSV stopped at 25 uploaded rows and zero drafts. A read-only check confirmed the affected job is uploading, with 25 rows persisted and no created drafts. Its hash matches the supplied CSV. No event logs were available for the failed request, so a specific network/edge failure cannot be established retrospectively. The confirmed usability and resilience gaps are a generic error, no automatic transient retry, no explicit upload-resume action and retransmission of already stored rows.

Preserve current authentication, CSRF, owner-only jobs, atomic D1 commits, file-identity matching and draft-only creation. Add an owner-scoped staged-row manifest, exposing row numbers only. Resume the same file/job by uploading only missing rows. Use ten-row/96KiB target upload batches while retaining server-side bounds. Retry only transient network/timeouts and HTTP 408/429/5xx failures, at most two retries per request; preserve mutation bodies and honor bounded Retry-After. Do not retry authorization, validation or conflict failures automatically.

Expose upload, validation, draft-creation and completion separately. Explain why uploaded rows do not yet count as drafts. Provide Continue upload in history, detect already completed files, retain the selected file for retries, support pausing through an AbortSignal, and show safe HTTP/request-ID/field-path diagnostics. History errors must not hide the import error. Preserve intentional duplicate retention as an explicit choice.

Validate real local D1 recovery of a 25/45 mixed-question job, lost responses after upload and commit, noncontiguous saved rows, repeated completion, cross-owner denial, bounded retries, throttling and cancellation. Browser checks should exercise the worker parser and UI with injected response failures; no real user credentials, production fixture accounts or private question content belong in committed tests. The existing live import must remain intact for its owner to resume through the normal authenticated UI.
