# Screen contracts

These 21 screen variants cover the 20 routable screen patterns in the current student and teacher routers (the optional editor pattern has separate new/edit contracts). The `/admin/*` routing boundary and catch-all are recovery infrastructure, not extra screens. All contracts are proposed; none are implemented by stage 1.

Each row specifies title/task, dominant task action, secondary/navigation actions, status and recovery, layout and implementation milestone. Primary actions vary by state but only one is dominant in a task region. A destructive action is never presented as the ordinary Next action. [Navigation](NAVIGATION.md) supplies shared history, focus, modal and saving rules; [layouts](LAYOUTS.md) supply annotations; [journeys](JOURNEYS.md) supply complete transitions. Page-level title is one h1; section labels follow a logical heading hierarchy. Copy below defines English meaning for later explicit translation.

| ID / route / title and task | Dominant action by state | Secondary/navigation | Status, empty/unavailable and recovery | Layout / milestone |
|---|---|---|---|---|
| R01 `/design` — Design reference. Inspect component contracts. | Choose component/state example; no product conversion CTA. | Theme, density, language, state controls; Home return. | Explicit internal reference; named loading and bundle-failure Retry where supported; every specimen reports its own chosen state, not fake app data. Shared fallback F01: missing entity retains its appropriate frame, gives an Unavailable h1, concise reason when known and one dominant safe return. It preserves existing stored data and never rewrites a missing ID into another entity. Invalid review position returns to the same result, unknown teacher path to Overview, unknown top-level path to Home. Direct browser links work without stored return context. Lazy loading announces Loading workspace/reference without a blank main; load failure offers Retry and a safe return. Offline alone is not an error for already-loaded local data.

## Component states inherited by every contract

Controls require default/hover/pressed/focus-visible/selected/disabled/loading/error/success where meaningful. Loading/disabled alone must not obscure the reason an action cannot proceed. Primary data changes state after successful operation, not an optimistic toast with no effect. Use text/icons alongside color. All labels, help, error text, accessible names and dynamic counts are explicitly translated; question content retains its own language metadata. Stage 2 defines the component state matrix and measurements; stages 3–8 apply it according to these contracts.
