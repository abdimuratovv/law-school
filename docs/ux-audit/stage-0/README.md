## Main findings

The most urgent risks concern saved work: a failed local write is not surfaced and loses the new answer on reload; teacher editor drafts disappear after reload despite an autosave timestamp. These are documented for the relevant implementation stages, not silently changed during baseline collection.

Three further behavior assertions fail: the desktop map traps focus without declaring modality, the documented ArrowRight exam shortcut does not advance, and shared segmented radios lack arrow selection/roving focus. The issue register additionally covers target-size candidates, missing main landmarks/loading feedback, localization migration, teacher demo boundaries, unknown editor IDs, density and unmeasured composed contrast.

Working behaviors confirmed in the browser include repeated-choice stability, explicit clearing, persisted practice checking, choice/written answer reload, offline messaging, submit preserving answers, preliminary results, review content, absolute timer deadline preservation, expired-session auto-submit, demo OTP and visible-title search in all three languages. Import and builder remain frontend previews.

`npm run typecheck` and `npm run build` both passed. The existing production build output was regenerated by validation. Browser automation uses installed Google Chrome because the Python Playwright package has no bundled Chromium in this environment. The skill's server helper is also absent; Vite was started directly. There is no Git repository in this workspace, so there is no commit or branch to report.

## Acceptance gate

The baseline gate passed: all 414 matrix records and referenced files exist, with all expected route/theme/language/viewport combinations represented. There are 22 additional interaction captures. The matrix recorded no unexpected redirects, JavaScript page errors, horizontal document overflow or unnamed-button candidates. This does not establish that all controls have correct accessible names. Target-size candidates appear in 276 captures, and 13 route variants lack a main landmark; see the manifests for exact evidence.

Every route has a primary task and testable state list; historical findings are explicitly resolved, reproduced, partly resolved, or unverified. Existing application failures are allowed in an evidence-gathering stage and remain tracked for implementation.

Full screenshot collection does not imply every image received detailed human-style visual review. Representative exam and teacher screenshots were inspected, and all captured pages were checked programmatically for route destination, JavaScript page errors, horizontal document overflow, landmark presence, unnamed-button candidates and interactive bounds. Native language review, composed contrast measurements, assistive-technology testing, zoom/reflow stress, longest-question testing, performance comparison and real student/teacher sessions are still outstanding as described in the checklist.
